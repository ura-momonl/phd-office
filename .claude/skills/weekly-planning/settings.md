# 用户的常驻排期设置

只有「可工作时段」「重复占用」「日常限制」写用户亲口给过的信息，未提供的保持「未提供」，不要猜着填。估时表是例外：用户说过估时先随便给，所以下面是助手的粗估（标「粗估」），用户纠正后改成用户的值并注明来源。

写法：`- 项：内容（来源：用户 YYYY-MM-DD「原话」；更新 YYYY-MM-DD）`。改动时在原条目上更新并改日期。

- 通常可工作时段：09:00–17:00；本次计划范围为 2026-10-19 至 2026-10-23。长期适用的星期范围、周末是否工作未另行说明，不据此推定（来源：用户 2026-10-17「通常可工作的时段为9：00-17：00」；同一对话「搞错了19-23的」；更新 2026-10-17）。

## 重复占用
- 课程、助教等固定占用：用户本轮未另述，按 calendar 中已有的重复事项核对，不将未提供视为“无”（更新 2026-10-17）。
- 午饭：必须留出吃午饭时间；具体起止时间和时长未提供，预览中的建议不视为用户已确认的常驻设置（来源：用户 2026-10-17「留出时间吃午饭」；更新 2026-10-17）。

## 工作量预算口径

- 助手代做的任务也按估时计入用户本周工作量预算；这部分是代做抵扣，不是用户实际亲自工作的时长，不因为助手代做而继续给用户增加任务。实际个人日历占用与包含助手代做的预算分别列出（来源：用户 2026-10-17「记得把助手工时也算进我的工时，这样才能让我轻松」；更新 2026-10-17）。
- 当前 weekly 程序的 capacity 只统计用户自己做且可排期的目标，助手目标不占个人日历；因此程序返回值不能单独代表上述总预算，须另列助手估时并核算。这是本次已读 weekly/README.md 与实际 preview 的已知限制，不代表用户要求被取消。
