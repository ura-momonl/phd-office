# 单一续接入口与助手分工

DeepSeek 从 `resume.mjs deepseek` 定位自己的包，再用 `launch.mjs deepseek <包ID>` 取串行 `next_task`。她用 `first-pass.mjs` 做首轮并读精简复核，流程见 SKILL.md 的 DeepSeek 一节；下文的并行派工描述指 Codex／Claude。未分配包时显示空状态，不改两位现有归属。后续内容核对和持锁提交仍用共同入口，记录本人实际完成的动作。

## 新对话的一次批量续做

1. 用`resume.mjs codex`或`resume.mjs claude`读真实状态。它指向`CONTINUE.json`，不是搜索出来的旧交接；catalog实时数量高于写死摘要。若续接表与实际数据冲突，先核对相关ledger/delivery，不重建已完成的池。
2. 先读本人`packages`的manifest、reader_guide和唯一选文标准。尚有未读输入时，先单独调用literature-dispatch生成子任务plan；这里只领取返回的task做阅读/核对，不再现场实现另一套切块。`pending_work`是精确范围，`selected`不是整轮上限；按reader-operations.md有界读取和及时落盘。
3. 子块输入和结果路径互不重叠，子agent只写自己文件，不能并发写原大work item输出。主助手用merge命令串行合并合法连续前缀，缺口后的已交付结果留在子文件，不覆盖或丢弃。已经有子agent在读的范围先收拢，不能因尚未落盘而重复切派；当前有效前缀自动跳过。
4. 主助手持续收拢本阶段输出，实际校验字段、范围、UTF-8、证据、类型、摘要来源；对已有误判的便宜初筛安排强复核，并对照原文验收。完成一块就接本人下一块，不把读完30篇当最终交差。阶段汇报给实际完成量、路径和待核项，不回贴全体摘要。
5. 两位主助手各自验收本人结果，分别调用admit-reviewed.mjs持锁登记、读回核验；Claude不转交Codex。不要调用旧的仅Codex写库脚本或直接覆盖catalog。模型间一致、格式合法或只做初筛均不等于已验收。

## 不抢活与开辟下一段

- **现有任务身份**：`owner + input + start_index/end_index + 唯一output`。只分配自己的块；别人的输出未出现不等于别人没在读。两位助手各有一个独立工作对话；同一owner不要在另一个活跃对话重复启动同批。
- **原范围稳定、子任务可拆**：原work item ID/owner/边界不改；分派skill可在其内或跨同owner多个范围生成独立子输入/输出，再由主助手合并。正在跑的范围先收拢，不因没有落盘就重派。更改owner前由原负责人确认未在运行。
- **新来源段**：由CONTINUE.json指定的独立协调对话先核对覆盖台账、已登记来源及所有包范围，选择未覆盖的完整“期刊＋连续年份/日期段”，先登记归属再采集。两条工作对话不自行领取新目录。不能按题名词、引用数或随机抽选凑新包。
- **落盘再切包**：协调者保存目录、分页和实际边界，去重后生成真实输入，再按每人约500–1000篇发布包manifest、owner与唯一结果路径。旧块可以组合，不改已经领取的范围；缺摘要保留待核，不用假记录补足包数。取数中途失败只发布已实际取得的部分并保留未取游标，不能把全年保留范围说成全年已取齐。
- **续做而非后台自转**：工作者持续处理本人整包，包用尽交回协调者登记下一包；不自行抢新源，不宣布全库完成，不另建轮询。真实上下文、额度、工具限制或用户暂停时留检查点；不是每完成一个文件就等催。协调者与写库者具体职责及不并发改共享字段的方法见coordinator.md。

## 进度只维护一处

`CONTINUE.json`保存当前授权范围、目录与审阅交付依据、唯一写库者、未读块的owner/输入范围/输出路径，以及尚未解决的来源和边界事项。它是本次具体工作状态，不是调度器：不会因存在ready条目就启动模型、卡片或后台任务。

阅读者只交付自己的结果文件，不同时修改共享续接表。只读入口依据文件实际条数判断“未做/部分交付/已交付待验收”，因此即便共享表尚未由写库者收尾，新对话也不会把已交付块重复派发。遇到损坏、非前缀或ID错配的已有输出就报告待修，不能当空白重新覆盖。

本人主助手通过共同入库命令只更新本人验收ledger/delivery、对应状态及catalog统计；协调者只增补来源、包和分工。命令持锁写catalog，修改共享表前重新读最新版本、保留对方字段并比较并发变化；失败保留入库回执，不从旧快照覆盖。未分配池游标与未取目录分开登记，保留pending和原始判断。

## 两种进入方式

- Codex工作对话：按Codex分工领取本人主包；需要切子块时单独调用literature-dispatch，再批量阅读、风险复核并自行验收入库，不接管Claude验收。
- Claude工作对话：按Claude分工领取本人主包；同样独立分派、阅读、风险复核并自行验收入库，不转Codex。

这是角色分工，不是模型优劣保证。用户可另行指定模型/归属，但不要把单次50篇试跑或一次成功当成1000篇质量承诺。各自只在用户发起的工作轮里按当轮授权推进。
