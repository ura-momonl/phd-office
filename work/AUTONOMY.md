# 项目自主推进

控制路径：用户实验步骤完成并填写 `outputs` 或 `handoff`，或标记失败（连带终止后续依赖步骤）→ 队列保存新进展事件 → 同一操作组全部结束 → 现有 `drain` 合并事件、创建一次“项目推进”任务 → 助手判断并维护框架／步骤 → 现有执行器按权限接续。

## 配置与权限

入口是 `automation/config.json.autonomy`，不修改旧的 `ai.automatic`。当前 **L1**：自动规划可执行，普通自主步骤只建 `open`。L2 允许 A 档助手步骤排队，默认链深 1；L3 默认链深 3；L4 当前沿用 L3 上限，没有额外对外权限。改变 `level` 即按对应链深生效；L0 关闭自主规划及未批准的自主执行。

- A 档：`data`、`literature`、`mail`（只起草）、`framework`、`presentation` 中的本地可逆工作。分类不能授权实际发信、付款、仪器操作或删除原始资料。
- 用户实验及其他提议留在 `open`，用户在原有看板状态入口接受后才可进入待办；`actor:user` 永不由助手执行器执行。
- 普通聊天当前回合中，助手替用户创建／启动明确交办的步骤沿用原有规则，不额外要求自主三要素，也不必再去看板批准。程序核对真实的活跃父任务、执行者及保存的聊天来源，新步骤用 `delegated_by` 指回该回合；请求自称聊天来源或批准无效。自主规划派生及无父任务的后台 CLI 创建仍受等级闸门约束。
- 用户可在普通聊天明确接受已有自主步骤，或在原有看板状态入口接受；程序保留来源、批准时间和批准入口，撤回到 `open` 会撤销排队批准。后继建卡的接续资格只看来源：正在执行、已获授权的项目操作步骤。该步骤创建的助手后继登记为 `queued`，`delegated_by` 指向来源步骤；不要求同项目、同日志主题、特定工作类别或直接依赖来源步骤，不自动补日志主题或依赖。节点内容与依赖由执行 agent 决定。建卡时即使沿用旧调用的 `status:open`，也按接续关系排队；建卡后的手动状态修改不受影响。用户步骤仍由用户执行；聊天轮、自主规划及未经用户接受的自主步骤沿用原规则。已有自主链不会因进入聊天而重置权限。
- 初始每项目自主并发 1，待处理自主步骤最多 3，每本地日自主执行最多 6 步（**包含规划，不是精确模型调用或 token 上限**）。时区沿用 `weekly/config.json`。被上限挡住的任务保留在队列，`work list`/`work handoff` 可追溯来源；可执行状态附暂停原因，不阻塞无关后台维护。

## 自主建步骤

`work add` 的自主步骤归属一个项目，并填写 `sources:[来源]`、`decision:会改变的后续决定`、`deliverable:交付物`。程序从当前实际执行任务继承父任务、根任务、事件哈希和链深，不能通过请求伪造 `autonomy` 或 `progress_event`。规划是深度 0，派出的第一步是深度 1。排队和实际启动都检查权限；降级后已排队但未启动的任务也暂停，正在运行的一步可以正常交付。

业务操作在 `work update` 明确提交 `status:done` 时，沿用显式登记的 `require_outputs` 和 `log_requirement` 约定；执行器不再从回复抓路径或用文件写入事件判断交付。项目日志只收对项目有长期帮助的研究内容；普通操作记 `logs/`，不因项目归属或日志主题挂靠自动要求项目日志。新增或修改计划不代表实验发生，也不代表用户接受了新实验安排。操作及其原位成果在 `work/queue.json`，每次执行记录复用 `work/turns.json`，没有新增工作状态库。

产出位置沿用用户指定或项目现有目录；完成时通过 `work update` 提交 `status:done`、`handoff` 与 `outputs`，路径可用办公室根目录相对或绝对路径，纯说明可无文件。普通聊天回复结束即结束本轮；操作未提交完成则回到现有 `open`，保存回复和执行历史，显示「上一轮已结束，未提交完成」，不自动重跑或假称需要用户处理。问题或验收卡由 agent 明确创建，不由文件类型自动推出。

## 按需子操作和重复执行

一般工作保持单节点；需要可见、可恢复的探索过程时，agent 用 `work add` 的 `parent_id` 归类子操作，`dependencies` 单独表达真正前置。父归属不作启动条件，子操作完成也不自动推出父操作完成。现有前置关系保持 DAG；回到一个操作再分析，是新的执行，不是新增相互等待的依赖。

调用子 DCG 后，父 agent 以目标、路线、结果判断与整合交付为主，子操作承接具体执行；父项保留必要的证据读取、抽查和少量衔接。未调用子 DCG 的任务仍直接做，执行输入中的分工说明由 `rule/work-completion` 统一提供。

子操作未另填归属时沿用父操作的 `project_ids` 和 `plan_node_id`；显式指定其他项目时不沿用原框架位置。执行输入带父操作目标、资料入口和已有成果。重复执行的框架上下文读取原操作当前的绑定，不依赖旧会话记住它，也不复制一份框架状态。

`work run <UTF-8 JSON文件路径>` 接收 `{id:操作ID,input:新输入或下一次执行方向}`，明确安排一次执行，复用原操作会话。执行记录带 `operation_id`，首次执行的记录还带 `source_task_id` 指回原会话任务。运行的 `status` 表示本轮是否结束，`outcome_status` 表示这次操作提交结果；未提交时前者为 done、后者为 open。原操作不反复 done→active，原成果保留，直到负责的 agent 明确提交新结果。历史与当前执行都从同一份 turns 记录读取，不另建循环器、状态库或分类模型。旧 `exploration` 字段仅保留历史，不再由「续跑」行、文件时间或轮数来启动、暂停任务。

需要收回子操作结果时，父 agent 在派出子操作后登记 `work run {id:父操作ID,input:回来后要继续解决的事,after:[子操作ID或执行ID]}`（仍通过 UTF-8 JSON 文件调用）。`after` 等指定步骤的本次执行结束，成功、失败、取消或本轮未提交的结果都会返回；与要求前置成功的 `dependencies` 分开。指定操作 ID 时看其最新执行，并一并等候其名下（parent_id，任意层）仍在执行或排队的子操作；指定执行 ID 时只看该次执行。现有派发器接回父操作原会话，输入带回结果状态、已登记说明、执行说明和成果入口；父 agent 决定换路线、再分析或明确交付。未登记返回就不额外唤起，不自动完成父操作、不自动重试，也不新增模型判断、轮询或状态库。

## 发现上一环有问题时

下一环（规划或执行）发现已有步骤、拆解或前置结果有误：
- 前置、交付物、目标歧义等小而明确的错：直接改该步骤，在留言／history 写一句改了什么、为什么，然后继续。
- 会改变范围的问题（拆得不对、缺关键实验）：停下，发 decision 卡，写清哪里不对、建议怎么改、影响什么。
- 不静默重做，也不照着错的做完；不改用户实验步骤的状态或结论，只在留言如实记录。
- 不新增“打分／回退”状态或复核模型，沿用步骤编辑、history 和卡片。

## 事件与停止

- 只接收新代码启用后的用户项目实验／项目步骤完成或失败事件；完成须有 `outputs` 或 `handoff`，失败本身即可记录事件，不要求有数据文件。不补跑历史已完成／失败任务，也不激活旧的 `open`。
- 操作步骤新转为失败时，同项目内沿 `dependencies` 传递，将尚未结束的后续步骤标为失败，在 `history` 留下根前置的 ID 和原因。无关分支、已完成／取消／删除项、对话轮和正在执行的助手不改；保留原负责人、留言和产出，不自动重试。连带失败不各自产生进展事件。
- 挂在同一日志主题（`plan_node_id`）下的步骤，要等该主题里没有 open／queued／active／waiting_user 的步骤（全部 done／cancelled／failed）才触发规划，整块合并成一次；不挂主题的步骤仍按单步触发（2026-10-17 用户提出）。已完成的规划步骤不再出现在“待归入日志主题的步骤”里。
- 同一来源、完成批次、路径和留言得到同一事件哈希；无变化的保存不重新触发。更新已完成步骤的实际输入会生成新事件。30 秒防抖合并同项目新事件，沿用既有后台节拍，无新定时器。
- 规划任务本身是持久去重凭据；完成、失败、取消或“无需新工作”均不自动重放该批事件。后续真实新进展可以形成新一批。
- 助手自己的产出不产生用户事件；子步骤只继承并消耗链深，不能重置为新根。没有新事件不新增规划、不调用规划模型。当前不监听原始数据文件、不以邮件触发规划、不自动升级等级。
- 框架与任务的语义判断由助手负责，机械权限由程序校验。**这是工作队列的权限边界，不是针对任意 shell／HTTP／文件写入的安全隔离**；助手仍须遵守已有工具权限和对外动作审批，不能绕过队列限制。

## 验收

`node scripts/run-tests.mjs --autonomy --keep` 创建脱敏隔离副本，使用假事件、合成说明和替代模型执行器验证 HTTP 完成／失败入口、后续依赖连带失败、整组结束后一次规划、CLI 来源继承、去重／无事件、L1/L2/L3、手动批准、降级、并发和日上限，并回归原有任务工作流。不连接真实模型或测量仪器。

后端加载新代码需等活动任务结束后正常重启。真实 graphene 数据到来后的科学判断、文件适配、看板内容质量和长期额度表现，不能由这些机制测试认证。
