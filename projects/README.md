# 按项目组织工作

项目是上下文的中心。邮件、采购、实验、数据、文献和 PPT 是相互关联的事项、证据或交付物。功能模块负责执行，项目层记录“为什么做、与什么有关、现在要解决什么”。

项目页已有的「关联资料与杂事」用于邮件、会议与约会等事务，不进入研究逻辑线或时间线；对研究有明显作用的内容才提炼入研究框架。已关联邮件（含完成记录）、未绑定研究节点的 `mail`／`misc` 操作步骤、该项目的日历事项（含已发生的日程）和文献由原模块提供，界面按项目汇总，不复制正文。对研究有实质作用并显式绑定研究节点的操作步骤仍显示在该节点。

额外的事务笔记可在此栏点「添加资料或杂事」，或运行 `projects related-add <UTF-8 JSON文件路径>`：`{project_id,title,kind?:mail|meeting|material|misc,body?,date?,source?}`，日期不明可留空，source 可引用原信 ID、对话或文件路径。笔记存在 `projects/catalog.json` 对应项目的 `related` 中，不改 `FRAMEWORK.md`，不会创建待办、日程或对外动作；需要待办或日程时用原模块维护，避免另抄一份。`projects related <项目id>` 读手工笔记，`projects context <项目id>` 同时返回 `related` 和 `calendar`，以及原有邮件、工作等入口。

当前 catalog.json 从原 PROFILE 的三个研究方向建立入口，并单列教学与博士事务；用户已确认现阶段分组符合工作组织，之后允许 AI 随实际任务调整。项目目标和当前问题不再单设字段（2026-10-11 起移除），研究内容以各项目 FRAMEWORK.md 为准；没有编造进度或实验结论。项目目录不复制任务状态；读取上下文时从原账本取最新行动和草稿路径。

```powershell
& 'D:\Program Files\nodejs\node.exe' automation/run.mjs projects list
& 'D:\Program Files\nodejs\node.exe' automation/run.mjs projects context bi-devices
& 'D:\Program Files\nodejs\node.exe' automation/run.mjs projects context unassigned
```

程序只读出所选项目相关的事项，不调用 AI。这个输出可作为后续 Codex/Claude 的上下文入口；当前邮件粗筛会保留命中研究关键词的资讯，但关键词仅是关联候选，不证明属于该项目。

## 项目框架（FRAMEWORK.md）

有研究经过要长期记的项目，在项目目录里放一份 `FRAMEWORK.md`：标题层级是嵌套板块，下一行 `<!--node {...}-->` 记日期、关联与研究标记，正文自由。`type:logic` 是逐渐形成的论证地图（动机、关系、证据、边界和证据缺口），不放实验试错或今天／明天的步骤；`type:timeline` 是完整研究日志，按主题与子板块嵌套分类，不按月份分栏。T- 记录直接嵌在所属主题或尝试下，日期与相对先后仍保留，未知日期不移出主题，详细记录只有一份。失败、尝试、当时的判断和计划保留在日志中。当前操作按 work 的 plan_node_id 整合到对应日志主题的步骤区，不另设“当前执行”；状态、留言和自动化只读写 work，不混进研究论证或历史正文。未绑定日志节点的事项显示在日志内“待归入日志主题的步骤”，不自动猜归属。

追加记录、加板块、改研究标记、关联、补日期用 `projects entry-add／node-add／node-status／node-link／node-set`（`help projects`）。entry-add 的 `parent` 指定日志中的主题或子板块 ID；不填则暂列“尚未归入主题的日志”，不从关联猜分类。逻辑问题和其他日志入口通过 links 引用同一记录；评价、备注、缺项和原讨论入口独立折叠。写法见 `projects/FRAMEWORK-RULES.md`。catalog 不存框架节点，来源草稿不当作已成立的文章论证。

日志按内容确定粒度：可独立命名、讨论和判断进展的研究环节开子栏，原因、参数与备注留在详情；不因 T- 编号机械套阶段。主题本身就是一个环节时可直接放记录。多种方法共用的原叙述只放在共同父栏一次，各方法引用；不为补齐排版虚构独立记录。单条记录不再套“详细日志”层，已有内嵌正文不重复列相关记录按钮，跨栏引用仍保留。

阶段内的日志使用轻量详情行，不合并内外 ID 或正文。阶段／尝试／说明子栏恰好只有一条直接日志、没有子栏及操作步骤时，打开父栏即露出日志详情；用户手动折叠优先于默认，刷新不把隐藏子项的开合当成用户选择。阶段和日志的编辑、附件、研究状态及引用仍各归其节点：文字编辑只保留标题旁一个入口，附件放在各自操作行，分别标明“给本栏添加附件”和“给本条日志添加附件”；外层删除按钮标明包含几条日志，内层为“删除本条日志”，原保护与确认规则不变。

### 数据处理也是日志

日志是实验和处理的主要记录。处理完在对应测量子栏用 projects entry-add 新增日志，保留输入路径、方法/参数、脚本与版本、输出路径、结果与限制，links 引用原测量记录、work 引用本次处理任务。重新处理另开日志并关联旧版，不覆写原始数据与旧判断；逻辑线只引用证据。

work add/update 可显式配置 log_requirement:{project_id,parent,links:[已有原记录或上下文日志ID]}。完成检查读取真实 FRAMEWORK.md：该 parent 下须有非空 T- 记录，work 含本任务 ID，links 含要求的原记录；require_outputs 仍须交付存在的分析文件（不能只交 FRAMEWORK.md）。未满足则自动步骤等待用户、后续不放行，也不重试。此要求不启动助手、不授权发信，不核定科学正确性。记录不全、证据缺口先记下来，只有用户明确决定执行才新增操作任务。

## 项目页便捷编辑

新增入口简化为“子栏／日志／操作步骤”。子栏默认不带灯，只提供“带状态灯”开关，不要求选择说明／阶段／尝试；已发生的尝试可直接记日志。已有 kind、编号和状态不迁移。说明性祖先不允许子栏带研究灯时，开关禁用并解释原因。

补充详情只按显示合并：评价与讨论、来源与更正、缺失信息（逻辑线显示“还缺什么证据”，日志显示“待补记录”）；关联说明单独保留。原标签、作者及日期、观测／仿真／解释／计划的区分、更正与对话引用均保留；空组不显示，缺失信息不自动转任务。

日志主题、子栏或单条日志内可“＋ 操作步骤”：标题、说明、负责人和本项目前置步骤。默认负责人为用户；新增项唯一存在 work，状态为 queued，auto_start 固定 false，保存不启动助手或发送邮件。`GET /api/work/new?project=<id>&node=<id>` 读取归属与前置选择，`POST /api/work/add` 用 `{project_id,plan_node_id,title,goal?,actor?,dependencies?}`，服务端重新验证日志节点和前置是否存在；不接受自动执行授权。已有自动化链不变，需自动执行的后续仍须单独明确配置。

新增子栏／日志直接归入打开入口的板块，不再重复选择“所属板块”。

项目详情“本周重点”下方的“编辑栏位”开关控制编辑模式，与“归档项目”“与 agent 推进”一起放在右栏；桌面右栏滚动吸附，窄屏下排到框架后方。关闭编辑模式时页面只读，所有编辑入口（编辑、＋ 大板块／子栏／日志／操作步骤、删除、编辑步骤）和拖动手柄“⠿”都隐藏；开启后全部出现，每栏标题旁“编辑”修改本栏标题／摘要／原文，展开后可新增子栏、追加日志；再点“完成编辑”退出（切换项目也退出）。备注、评价及讨论标签保持分栏，编辑不包含子栏。

编辑模式下用手柄拖动大板块、子栏、日志或操作步骤来重排和改归属，替代原来的“移动归属”对话框：落在目标行中部＝放进它里面（排在末尾），落在上沿／下沿＝放到它前面／后面，成为其同级；步骤落在日志节点上＝改挂靠，落在另一步骤的上／下半＝排到它前／后（并挂到它所在节点）。每个节点（含板块根部和“待归入日志主题的步骤”）的步骤块标题行还有一个手柄，整块拖到另一个日志节点上＝这一块步骤按原顺序整体追加到目标节点现有步骤之后；块里有任何一步正在执行或已交给助手就整块不动。不允许的落点不会高亮。移动携带子树并保留 ID、附件、研究灯和任务绑定，仍仅在同一内容线内进行（逻辑与时间日志不混搬；日志只进时间日志、不放进单条日志；最多六级；不能移入自己的子树；大板块只能在顶层重排）。后端：`POST /api/projects/edit` 的 `{action:'move',id,parent,before?|after?}`（`before`／`after` 是新父级下的同级条目；都不写＝放到末尾；拖动不带 `revision`，按 ID 和位置在当前文件上重算，落点没变则文件不动）；步骤用 `POST /api/work/move` `{project_id,id,plan_node_id? | before? | after?}`（整块用 `ids:[…]` 加 `plan_node_id`，不接受前后定位；落到节点上一律追加在该节点现有步骤之后），只改挂靠和队列内顺序，不改状态、负责人和前置，执行中或已交给助手的步骤不能移动。拖动期间页面暂停 5 秒轮询的重绘；触屏不支持。改字或移动都不自动推进任务。

五秒刷新不影响草稿；保存检查完整框架版本。仅其他栏或研究状态更新时，文字编辑读取最新版后重试一次；本栏文字或日期变动时展示最新版，保留草稿，由用户核对后更新保存基线，不自动覆盖。结构动作仍拒绝旧版本。正文代码围栏必须闭合，失败不写入。

日志编辑里可补发生日期和确认情况；改日期自动撤销旧确认，明确重新确认才标已确认；保存原依据并追加日期更正。正文与日期一次写入／拒绝，不分两次保存。有效写入前的旧文件在 `.runtime/framework-edits/<项目id>/<SHA256>.md`，编辑面板列出备份时间和路径（不是实验日期），恢复前须核对后续修改，未提供一键恢复。删除需确认且通过引用／任务检查；历史理解变更仍应追加更正说明。`projects editor <项目id>` 读原文、revision 和备份清单，`projects node-edit <JSON文件>` 与页面共享写入规则；`content` 可附带 `fields:{date?,date_confirmed?,after?}`，也可单独用 `action:"fields"` 更新日志日期。状态和任务不能通过 fields 修改。

## 后续功能遵守的共同结构

### 编辑操作步骤与删除

时间日志里的每个操作步骤旁有“编辑步骤”和“删除”。编辑标题、步骤说明、负责人、留言及前置依赖，保留原 ID、状态、产出、绑定和自动执行设置；步骤说明可独立展开。`work editor <id>` 读取最新步骤与 revision，`work edit <JSON文件>` 使用 `{id,revision,action:content|delete,title?,goal?,handoff?,actor?,dependencies?,confirm?}`。循环、自依赖、已失效前置、旧版本、正在执行／已派给助手的步骤会被拒绝；已完成事项不能依赖未完成事项。

步骤删除需明确确认且没有其他步骤依赖它；后台标为 cancelled 并保留 deleted_at、历史及产出，从页面隐藏，不解锁后续任务。旧队列备份在 `.runtime/work-edits/<SHA256>.json`；不能通过普通 update 重开已删除步骤。

每个框架栏的操作区有“删除本栏”，显示子树范围并要求勾选确认。`projects node-edit` 支持 `action:"delete",confirm:true`，删除本栏及子栏／日志，保留完整旧框架备份和磁盘附件。确认删除时自动解除外部 links／corrects／after／正文记录引用和操作步骤绑定，保留相关步骤、状态与产出；最后一个时间日志板块不能删除。删除不会回收 T- 编号，新增日志不复用历史编号。不级联删除任务，也不新增模型调用。

项目和阶段节点都可用 `files` 数组登记资料：`{title, path, description?, name?, size?, mime?}`，`path` 相对于 `workspace/projects/<项目id>/`。阶段可用 `description` 存说明；说明和文件都不决定完成状态。工作台可直接给项目或阶段上传任意类型文件，不调用模型；每批最多 10 个、单个 20 MB、合计 30 MB，沿用聊天文件解码及限额。下载只允许登记且实际位于该项目目录内的文件，不接收任意请求路径。PNG/JPEG/WebP/GIF 根据实际文件内容识别并预览；其他文件原样下载，用相应软件打开，不执行上传代码。字段均可选，无须给其他项目填占位内容。

| 信息 | 要记录什么 | 为什么需要 |
|---|---|---|
| 项目 | 稳定 ID、目标、当前科学问题 | 判断什么值得做 |
| 事项 | 下一步、负责人、复查时间、所属项目 | 跨邮件和工具跟进同一件事 |
| 证据 | 原邮件、数据批次、文献、日期/工艺版本 | 可以核对结论及条件 |
| 结果 | 图、拟合、文献笔记、实验记录及来源 | 供后续分析、回复、汇报复用 |
| 联系 | 依赖、支持/反驳、共享资源、产出 | 判断哪些后续工作受变化影响 |

事项可以关联多个项目，共享采购只记录一份。联系应当来自证据或用户确认，不能仅因都涉及 THz 就强行归为同一项目。catalog 的 links 保存归属与依据；dependencies 只在真实依赖明确后增加，目前为空。

例如：阵列补印改变工艺批次；后续 I–V 数据与位置映射必须引用对应批次；分析结果可支持 THz 测量对象选择，也可用于组会图页。这是要建立的工作联系的示意。

AI 处理任务时取“项目摘要 + 当前问题 + 相关证据 + 本次变化”，不用全量聊天和所有项目历史。做 PPT 复用已有结果及来源；采购跟进只取用途、规格和供应商记录；数据结论区分观测、计算和机制假设。便宜模型可提议项目归属和信息类别，复杂科研或重要回复按需要补证据/升级模型。

初筛不能只有“通知/营销/重要”分类。与研究关键词、当前事项或待解决问题相关的资讯应保留供判断；明确无关的通知进入本地摘要。项目归属、状态变化和内容指纹未变化时复用先前结果，避免反复让 AI 从零归类。

无需先搭图数据库或复杂知识图谱。现在使用一个项目目录、现有事项账本和稳定引用；真实需求出现后再接数据/文献/PPT 模块。
