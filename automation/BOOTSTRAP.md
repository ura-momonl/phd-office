# 各模块当前雏形与下一步

这一轮的目标是可逐步初始化、可复用、能继续加功能的框架。普通程序收集与保存事实，AI 按需理解，项目 ID 串联事项和结果；不把所有模块都初始化成全自动。

| 模块 | 当前可用 | 还需接入 |
|---|---|---|
| 项目与文件 | 五个入口、按项目取上下文、文件夹与实验/数据/汇报模板 | 用户逐步补目标、问题和真实材料；AI 可调整别名/归属/子项目 |
| 邮箱 | 每十分钟增量读取、内容去重、非 AI 初筛、小批判断包 | 用真实样本验证分类后，再接便宜模型的事件触发判断；不按十分钟固定叫模型 |
| 采购 | 原采购记录、来源、报价缺项比较 | 型号/数量/用途、供应商候选、交期与到货信息；邮件只起本地草稿 |
| 文献 | DOI 去重/元数据、校园入口、全文路径/Zotero 引用、现成 Zotero CLI | 确认 Zotero、完成浏览器校园登录，逐篇验证全文获取；专题检索与笔记 |
| 软件 | 现有 AutoCAD/Fusion/Altium/COMSOL 路线、固定目录和启动条件 | 在明确任务中启动软件/接活动文档，做对应结果验收；Origin 示例仅保留参考 |
| 数据 | 项目 raw/processed/analysis/交付目录，批次/单位/方法模板 | 一份真实数据对应一个可重复脚本，默认 Codex 执行 |
| 实验 | 实验问题、样品/批次、参数、原数据、观察与假设模板 | 用户记录真实操作；AI 辅助准备与下一步设计，不能从邮件推断已经测过 |
| PPT/文档 | 现有文件技能、汇报 brief 和来源复用路线 | 一次真实组会材料接入，默认 Claude 组织叙事，按文件技能制作 |
| 分工与对话 | 自然对话与 @ 指定对象；执行器自动领取明确请求，保存原生会话 ID 与短交接 | 逐个验收真实研究任务；默认不让两 AI 同时写同一事实 |
| 双 AI | 只靠 @ 路由，AI 回复里行首 @对方 即转交，每条消息最多 4 轮 | 测试覆盖路由、转交和上限；真实 Claude→Codex 转交已跑通一次 |
| Discord | discord.js 命令入口，沿用电脑端执行器；对话/收件箱/周计划/用量查询 | 本地 Bot Token 与本人/服务器/频道 ID；首次真实收发验收 |
| GUI | 对话、统一收件箱、项目、周计划与复盘、结果交接、额度、连接；桌面检查通过 | 按真实使用逐步补功能，手机暂不做 |
| 周材料与用量 | 周一 09:00 普通程序汇总；实际调用记账与 Codex 账号额度 | 用户逐步补研究记录，Claude 账号余额暂从官方 Usage 记录；组会 PPT 待真实材料 |

## 文件怎么放

```text
D:/Main/PROFILE.md                    原个人背景
D:/Main/assistant/
  projects/catalog.json               项目目标/问题、既有事项关联
  work/                               默认分工 + 新工作请求（不复制邮件任务）
  agent/ weekly/ usage/               执行器、周材料、实际用量入口
  procurement/ literature/ software/  各模块事实/来源/接入口
  workspace/
    inbox/ outbox/                    原投递与交付保留
    projects/<project-id>/
      inbox/ experiments/
      data/raw/ data/processed/
      analysis/ literature-notes/ cad/ deliverables/
    shared/                           共用材料；采购本身只登记一份
  templates/                          实验/数据/采购/汇报/任务模板
  vendor/                             上游源码与许可证
  .runtime/                           收件缓存、运行日志、工作安排表、本地凭据
```

已有 CAD/仿真/Altium 工程保留 D:/cad-ai、D:/fusion-ai、D:/Altium-ai、D:/comsol-ai 等原位，登记绝对路径；不搬动、不复制一套旧工程。文献全文留 Zotero/原文件，项目目录只存对应笔记和引用。

启动任何新对话，先读 AGENTS.md，再取一个项目上下文或一个任务 handoff。短交接保存目标、已核实事实/来源、输出、剩余问题和下一步；它比恢复一整个长期聊天节省上下文。长期事实更正写回拥有该事实的模块。

## 近期顺序

1. 你渐进补项目材料；Discord 配好后先验证零模型命令。
2. 用几封真实邮件/一篇真实论文/一份真实数据验证对应 AI 与软件路径，记录实际额度和误判。
3. 根据真实任务表现接事件触发的廉价批处理、主动进度通知；双 AI 的 @ 转交按需使用。复杂科学任务仍使用适当强度的模型。

没有当前问题或证据的地方留空，不为了“全自动”编造工作。只有确实有任务时才消耗推理额度。
