# 父级动态 DCG 编排

依据：用户 2026-10-28 明确父级负责架构整个子 DCG、判断并行与连接子框架；方法参考 [AgentTeams 的 team-coordination](https://github.com/agentscope-ai/AgentTeams/blob/main/manager/agent/team-leader-agent/skills/team-coordination/SKILL.md)、[Anthropic Research Lead](https://github.com/anthropics/claude-cookbooks/blob/main/patterns/agents/prompts/research_lead_agent.md) 和 [task-coordination-strategies](https://github.com/wshobson/agents/blob/main/plugins/agent-teams/skills/task-coordination-strategies/SKILL.md)。适用：本办公室父级操作按研究或工作目标组织持久子操作。验证范围：编排判断与既有队列接续，研究结论仍由实际证据支持。

## 父级负责的是路线，不只是派工

从用户要得到的结果和当前最关键的未知出发，决定用哪些子问题、方法路线和证据关系把目标做成。子操作负责具体分析、计算、检索或制作，父级负责架构、结果判断、调整和整合；必要的证据读取、抽查和少量衔接留在父级。让执行者自主选择具体方法，发挥她们各自的判断能力。

先读现有目标、当前操作和原位成果，形成能立即推进的一版图。研究信息不全时，把待确定处作为探索对象或暂定前提，让已有输入足够的分支先产生信息。图随证据演化，不把一次性列全未来步骤当作开工条件。

先让关键解释接受质疑，再投入精装交付：首批证据返回时，用实际研究图、定量比较和简洁整体稿，检查不同解释能否区分、分支能否在同一观测上连接、结论是否推进目的。父级先做这个研究判断，需要独立意见时沿现有协作入口交流，不新增固定检查层或例行模型调用；已配置的外层成果审查仍按原机制执行。所需数据浏览与研究并行推进，不为等排版或展示全部完成而推迟发现路线问题。

## 按问题与上下文边界拆解

一个节点应回答一个可辨认的问题，或产出一个能被后续真正使用的结果。选定切口时，想清它如何改变整体判断；按不同解释、证据来源、样品范围或相对独立的能力划分，比机械分成“读取—画图—写报告”更有帮助。

相关节点可以组成一个子框架。先确定它对外负责什么问题、接收什么已有成果、交回什么可用结果，再让内部执行者选择做法。跨子框架的连接落在实际成果的意义上：哪份比较、哪种约定或哪条判断进入下游，下游据此完成什么。保持每份共享结果和共同口径有明确负责人。

拆得是否合适，看这些子问题的结果合起来能不能推进父级目标，而不看凑出了多少节点。有用成果可直接复用，单个执行者几步能完成的工作保持在一个节点里。

## 设计并行、前置与汇合

对每条拟定连接，问：下游现在缺的究竟是上游的哪项输入？输入、约定或结果确实要由上游提供时才连前置；同属一个主题、安排在同一阶段，不自动构成依赖。

- **可以并行的部分先启动。** 独立证据、不同解释路线、互不覆盖的输出可以同时推进。共同前提尚未确定时，也可在写清暂定假设的基础上开展可复用工作；父级在汇合时判断哪些结论依赖该假设。
- **共享前提只由一处维护。** 标度、通道含义、输入版本、合并口径等由一名负责人交出可引用的结果，其他分支消费它；并行执行分别写各自的成果。
- **把汇合设计成研究工作。** 说明需要比较哪些分支、如何处理不一致、最后要形成什么判断。汇合不只是把几份子报告拼在一起。
- **优先推进关键未知。** 提前启动会解锁多条分支或改变路线选择的工作，同时让不依赖它的工作继续；并行规模随实际可拆性和资源安排，不预设固定人数。

例如，共同口径 P 可以连接到 A、B 两条分析路线，独立参照 R 可与 P 同时开展；A、B、R 的结果在 J 汇合。J 若提出新问题，由父级决定补哪条路线，而不是沿原清单走到底。

## 用现有队列承载这版图

具体参数使用 `node automation/run.mjs help work`。`parent_id` 表达父归属，`dependencies` 表达真正的数据前置；任务目标里写清当前问题、已有成果和输入输出的含义，交接采用办公室现有的自然写法。

将输入已经具备的节点交给现有执行器，派出后用父级的 `work run` 和 `after` 登记回来要判断的事。只等待下一项决策真正需要的结果：独立工作的部分不必为了同一波派出而全部等齐。操作 ID 等该操作本次执行及仍在进行的后续子操作；需要锁定某次结果时用执行 ID。

`after` 收回执行结束的实际结果，包括失败、取消和未提交；`dependencies` 用于需要已交付成果的后继。探索中“回来再判断、再做”的循环使用新的执行记录，保留静态前置关系的无环性。这里沿用持久子操作，不把可见、可接续的工作改成隐藏的原生子 agent；原生子 agent 的并发、层级与使用场合照现有约定。

需要父级判断返回结果之后才能决定的下游，先登记为 `open`，接受所需成果后再排队。尤其上游已有旧版 `done`、本次正用 `work run` 修订时，旧成果仍保留在原操作上；父级通过 `after` 收回本次执行，确认新结果再启动消费本版的下游，不能仅凭旧 `done` 放行。机械前置已足够表达的固定工作则照常用 `dependencies` 自动接续。

## 收到结果后重新判断图

读本轮实际交付、来源和关键结果，判断它对父级目标改变了什么。区分一个子操作执行结束、交出了候选结果，以及父级接受这个结果用于整体研究这三件事。

据此选择下一步：采用并解锁下游、补一个关键比较、沿新线索展开、调整共享前提、换路线，或整合交付。每次接续都指出新证据带来的具体变化，让继续执行有明确目的，而不是重新盘点或要求笼统“更深入”。

重规划沿用仍然成立的成果和稳定操作 ID。同一问题的补做用原操作 `work run` 接续；出现真正不同的问题再增节点。修改前置时使用现有步骤编辑入口，处理当前可编辑的节点；已经运行或交付的成果作为带来源的事实保留。某项前提变化，沿实际依赖判断哪些结论受影响、哪些可直接保留，局部补做并重新汇合。

接续只传本次发现、它改变的整体判断、需要继续解决的问题和原位证据入口，沿用仍有效的目标与共同口径，不把历次全文再抄一遍。报告、研究图和数据浏览器消费同一份可追溯结果；补分析后更新受影响的数据、图与解释，并在最终交付检查整体一致，不例行重制未变页面。给复审指出上轮问题对应的新证据及影响范围，审查者自主判断，不用自报“已解决”替代复核。

未定、失败或相互冲突的分支也能改变整体判断：解释它排除了什么、留下什么、现有资料还能怎样推进。对当前目标仍可由助手完成的关键分析继续组织执行；达到本次需要的研究信息与可用交付时由父级整合收尾，不强求预定物理结论。

## 保持一个可接续的当前架构

在父级原会话及原位成果中留下够用的当前说明：目标、正在采用的图、关键共享前提、可复用结果，以及回来后要作的判断。复杂图可用简短表格或图表示节点、输入输出和依赖，简单任务几句话即可。状态和执行历史留在现有 work 记录，不另外养一份调度账本。

父级最终交付整体结论和成果入口，子框架的作用由它们如何支持整体判断来说明。需要外层成果审查时，沿用已启用的父级审查机制：PI 审查针对整合成果，返工回父级重规划；审查不是子 DCG 的固定内部角色，也不代替父级设计与推进子框架。
