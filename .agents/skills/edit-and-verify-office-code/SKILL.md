本文只写做法，不抄命令用法：`run-tests.mjs` 的模式与含义看 `scripts/run-tests.mjs` 头部注释，沙箱权限、`--sandbox`、`--mail` 的授权路径看 `AGENTS.md`「测试与沙箱权限」。

## 做法

1. **探索一次发出。** 要读的文件和要查的引用点先列全，互不依赖的 grep、sed 放在同一轮并行发出，或合成一条命令。不要读一段、想一下、再读下一段。
2. **改文件用 Edit。** 批量机械改动才写脚本，并让脚本在锚点不唯一时直接报错。
3. **先选对测试范围。**
   - 聚焦模式（`--state-ui` 等）只跑 `--help` 所列的子集；改动跨面或不确定时跑全套。
   - 默认全量自动发现 `*.test.mjs`，Docker 仍单独用 `--sandbox`。`--list` 可不建副本查看清单；新增专项覆盖在 `scripts/test-suite.mjs` 维护。
4. **跑一次到位。** 命令写成「输出落盘 + 同一条里取摘要」：
   `node scripts/run-tests.mjs <模式> > .runtime/<名>.log 2>&1; grep -nE "^(✖|ℹ (tests|pass|fail))" .runtime/<名>.log`
   完整日志与 JSON 报告自动保存在 `.runtime/test-results/`，逐文件日志在运行中即可读取。失败时按文件定位，`--files=目录/文件.test.mjs` 可在新脱敏副本定向复验。全套耗时长，用后台运行，等通知。
5. **收尾。**
   - 自己用 `--keep` 留下的副本，结论定稿后自己清；只删自己这轮留下的 `phd-tests-*`，不动别人的。
   - 工作日志统一放 `logs/`，记录结果和验证证据入口；涉及命令用法变化时同步 `help` 文字。

## 不做

- 不借此放开任何权限或审批，不新增模型调用、轮询、定时任务。
- 不在真实项目目录直接跑会改数据的测试。
