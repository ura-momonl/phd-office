# 已入库文献重审

**依据**：2026-10-21 用新标准重审原有9009篇的实际做法。结果：保留84.6%，移出约12%（1104篇），其余留作边界；试点900篇、1900篇、2900篇、全量的保留率分别为84.8%、83.8%、83.9%、84.6%。**适用**：库里已有大批文章，标准变了或怀疑库太宽。**验证范围**：只在这一批（Nano Letters／PRL／ACS Nano为主）上做过，其他期刊先抽样再放大。

## 做法

1. **切块**：`node output/literature-rebuild-20261021/library-rereview/build.mjs --round <名> --all --size 100`，按稳定哈希排序，自动跳过前几轮已覆盖的ID，产出带哈希的task。第一轮用`--count 900`做试点，不要一上来全量。
2. **派读**：每块一个Haiku子agent，说明用[references/reader-prompt.md](references/reader-prompt.md)，只改任务路径。同时最多10个，一个结束补一个，不攒批。子agent走`brief.mjs`／`reader-work.mjs read/append`，**重审不走题名阶段**（已有摘要，直接判）。
3. **核对**：程序汇总全部`*-out.json`：条数、ID与输入顺序、枚举、evidence无公式标记、各批保留率。单个任务异常（保留率离群、`scope=out`比例特别高）单独看，别平均掉。
4. **抽核**：主助手各读约25篇被保留的和约25篇被排除的（按哈希随机），对照摘要。看理由是不是针对本篇、有没有把相关性当关卡。
5. **归类并移出**：`all-decisions.json`＋`out-split.json`→`apply.mjs`。只移出两类：agent没写任何犹豫的“相关但不收”，和主要贡献在能源／催化／电池／膜分离／生物学／生物医学的“范围外”（按唯一选文标准及2026-10-22用户补充）。agent自己标了“边界／可改收”的、三维块体的，保留并打标记。移出是`library_status=rereview-excluded`，记录留在catalog，`apply.mjs --restore`恢复。写库用入库同一把锁，先`--dry-run`。`literature/view.mjs`与`literature/run.mjs list`从2026-10-24起把该状态与`deferred-publication`一并挡在在库视图外；此前视图不过滤，移出后条目仍会显示。

## 审到哪里

- **估计比例**：1000篇的随机样本就稳定了（上面几个数几乎一样）。只想知道“库偏不偏”，试点就够，不必全量。
- **要逐篇移出就必须全量**：移出是逐篇决定，不能靠比例，所以这次跑了全部。以后同一标准下已审过的不再审，新批次按`literature-backfill`的入库流程在入口把关（题名先过，再读摘要）。
- **什么时候停**：覆盖到本次范围内所有ID；程序核对通过；抽核里理由站得住的占大多数（这次约八成），不一致集中在可命名的几类（块体层状、方法类、能源动机的器件）。到这一步就归类写库，**不做第二遍全量**，也不为统一口径重读全部；系统性偏差只对对应类别补审。
- **不属于本次范围的不顺手审**：别处新入库的批次（如这次的4928篇ACS Nano／Advanced Materials）要审另起一轮，先问清它们入库时用的是哪版标准。
- **目标指标看密封集**，不看移出了多少。移出只让库更“偏”，不会找回缺的论文；缺口在哪是发现入口的问题，不在重审。运行密封汇总程序只在有实质变化后，不反复刷。
