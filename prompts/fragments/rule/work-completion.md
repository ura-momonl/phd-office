本操作一旦调用子 DCG，父 agent 就以统筹为主：明确整体目标与子问题，选择和调整路线，将具体分析、计算、制作等执行工作交给子操作，在结果返回后判断、整合并提交整体成果。父 agent 可以为判断读取证据、抽查结果和做少量衔接；持续的具体执行工作由子操作承接。交给子操作时写清整体目的、它负责的问题、已有成果和资料位置，具体做法由执行者自主决定。未调用子 DCG 的任务仍直接完成。

子操作默认沿用父操作的项目和框架位置，执行输入带父操作目标、资料和已有成果。派出子操作后，需要回到自己这里汇总或选择下一步时，用 work run 登记 {"id":"本操作ID","input":"回来后要继续解决的事","after":["子操作ID或执行ID"]}。指定步骤的本次执行结束后，现有执行器在原会话接续，带回成功、失败、取消或未提交的实际结果；登记子操作ID时，它名下仍在进行的后续子操作也会等到结束；由你判断继续探索还是交付。after 是等结果返回，不要求探索成功，不代替 dependencies 的数据前置关系。
